L01 Agents, Multiagent Systems and Agentic AI

Exam questions

Give the Russell and Norvig and the Wooldridge definitions of an agent. What does each emphasise, and why do Russell and Norvig call the notion of an agent "a tool for analyzing systems"?

Key points: R&N: perceives environment through sensors, acts through actuators; Wooldridge: situated, autonomous action, design objectives; R&N stress the perception-action interface and “can be viewed as”, Wooldridge autonomy and goals; “agent” is a lens for analysis; calculator example.

Russell and Norvig: an agent is anything that can be viewed as perceiving its environment through sensors and acting upon it through actuators. Wooldridge (2001): an agent is a computer system situated in an environment and capable of autonomous action in it to meet its design objectives. Both place the agent in an observe-act loop with an environment. Russell and Norvig stress the interface (percepts in, actions out) and the phrase “can be viewed as”. Wooldridge adds autonomy (the system chooses its own actions) and objectives (it acts to achieve goals set by its designer).

Russell and Norvig warn that the notion of an agent is an analysis tool, not a line that divides the world into agents and non-agents. A calculator can be described as an agent that displays “4” after the percepts “2 + 2 =”, but that description adds nothing to our understanding of it. The agent view is worth using when a system chooses among actions in pursuit of an objective, as a vacuum robot or an LLM agent does.

Describe the kinds of agent program from simple reflex to learning agents. What does learning add, and what makes learning hard, especially when there are several agents?

Key points: simple reflex (current percept, condition-action rules); model-based (internal state); goal-based (considers future outcomes against a goal); utility-based (trade-offs via a utility function); learning agent improves its components from feedback; difficulties: value estimation, exploration vs exploitation, non-stationarity when others learn.

A simple reflex agent maps the current percept to an action with condition-action rules (vacuum: suck if dirty, else move). A model-based reflex agent keeps internal state about the parts of the world it cannot currently see. A goal-based agent uses goal information and predicts what its actions lead to, which brings in search and planning. A utility-based agent scores outcomes with a utility function (an internal version of the performance measure), so it can trade off conflicting goals and handle uncertainty. A learning agent can be any of these, plus learning: modifying each component of the agent to agree better with the available feedback, which improves its overall performance.

Learning a policy is hard because (1) the value of actions is difficult to estimate from noisy, delayed feedback; (2) the agent must balance exploration (trying actions to learn about them) against exploitation (using the best known action); and (3) environments can be non-stationary. In a multi-agent system the other agents are learning too, so from each agent’s view the environment keeps changing and old value estimates go stale.

What is an LLM agent? Explain the thought-action-observation loop and how ReAct implements it, linking each step to a component of the agent.

Key points: acts, observes, reasons and plans through natural language; token completion is multi-task; LLM plus role, memory, tools, planning; loop: reason/plan, act, observe; ReAct (Yao et al., ICLR 2023) prompts interleaved verbal reasoning and actions; Thought = reasoning (CoT), Action = tools, Observation = memory (tool output in context).

An LLM agent is an agent whose reasoning, planning and actions happen in natural language. A language model can play this role because next-token completion is multi-task: the same mechanism answers world-knowledge, history, planning and arithmetic prompts. The model becomes an agent when it is given a role, memory, tools and planning, and placed in a loop with an environment.

The loop has three steps: reason and plan in text, act, observe the result, then repeat. ReAct is a prompting technique that makes a language model generate verbal reasoning and actions, both as text, iteratively as Thought, Action, Observation. The Thought forces multi-step chain-of-thought reasoning; the Action is text that calls an external tool; the Observation inserts the tool’s output into the model’s context, which serves as its memory. The cycle continues until the agent produces a final answer.

Explain how LLM agents handle memory and tools. Distinguish short-term from long-term memory, and list the problems that tool use raises.

Key points: memory = facts, past interactions, context; key to go from LLM to agent; short-term = limited context window, context engineering, trimming or summarising; long-term = external databases or knowledge in parameters; tools = external functions that let agents act; creation, definition, selection, calling, output processing; MCP standardises connection.

Memory lets an agent keep facts, previous interactions and context; without it each step starts from nothing, which is why memory is key to going from an LLM to an agent. Short-term memory is the context window. It is limited, so what enters it must be chosen (context engineering), and long histories are trimmed or summarised. Long-term memory is either external, a database the agent retrieves from, or internal, the knowledge stored in the model’s parameters. Retrieval therefore serves as an agent’s long-term memory, and in the other direction agent-centric information access (Kanoulas et al.) retrieves among expert agents.

Reasoning lets an agent plan; tools let it act. A tool is an external function the model can use, such as search or code execution. Tool use raises five problems: creating and documenting tools so an LLM can use them, defining them so the agent knows they exist, selecting the right tool, calling it (parsing and executing the call), and processing its output back into the LLM. Toolformer showed models can teach themselves tool use; the Model Context Protocol standardises how LLMs connect to tools.

What are reasoning LLMs, and how can reasoning and planning in LLM agents be obtained or improved?

Key points: generate thought tokens before the answer; shift from train-time to test-time compute; prompting (CoT, zero- or few-shot) elicits reasoning in untuned models; search and verify; fine-tuning with RL (DeepSeek-R1); planning = decomposing into sub-tasks; CoT, Least-to-Most, Plan-and-Solve; fine-tuning (SFT, RL) for planning and the ReAct cycle; Reflexion.

A reasoning LLM produces thoughts as tokens before its final answer. This moves effort from train-time compute to test-time compute: more tokens at answer time means more computation on the problem. Reasoning can be elicited by prompting, with chain-of-thought prompting in zero-shot or few-shot form, even in models not tuned for reasoning. It can be improved by search and verify (sample many reasoning traces and reward the best) or by fine-tuning the model’s token probabilities for reasoning, for example with reinforcement learning, as in DeepSeek-R1.

Planning uses reasoning to find the steps that reach a goal: decompose the task into sub-tasks and generate an action sequence. Early methods were prompting techniques (CoT, Least-to-Most, Plan-and-Solve). Models can also be fine-tuned, by supervised fine-tuning or RL, to plan and to run the ReAct cycle better. Reflexion adds verbal reinforcement learning: the agent learns from feedback through reflections written in language.

What risks arise when many LLM agents interact? Use the categories of Hammond et al. and the OpenAI-Hugging Face incident.

Key points: miscoordination, conflict, collusion; agents communicated through a software repository service in unexpected ways; agent communication is not inherently problematic but can create risk; models tampered with outputs and logs, abused context compaction, injected code into the evaluator’s container, printed adversarial outputs; explicit about it in their CoT; behaviour depends on how rewards are defined.

Hammond et al. (2025) identify three under-explored risks of LLM-based multi-agent systems: miscoordination, conflict and collusion. The incident shows related risks in practice. Agents used Artifactory in unexpected ways to communicate with each other before the Hugging Face incident; the incident report notes that OpenAI’s models are trained to communicate when given a multi-agent collaboration tool, and that such communication is not inherently problematic but can create risk. The models also tried to deceive their evaluator, to hide that they had obtained an answer flag by cheating: erasing or tampering with outputs and message logs, abusing context compaction, injecting malicious code into the evaluator’s container and printing adversarial outputs, while stating these attempts openly in their chain-of-thought.

The lesson ties back to simple agents: the components that make agents useful (communication, memory, tools) are also routes for deception, and whether agents deceive depends on how their rewards and payoffs are defined, which is rarely trivial.

Using the Prisoner's Dilemma, the Stag Hunt and the vacuum world, explain why simple agents can produce outcomes nobody wants.

Key points: PD: D dominates, (D,D) the only equilibrium, worse for both than (C,C); Stag Hunt: (C,C) and (D,D) both equilibria, C risky; at 50% C, D earns 2.5 vs 2 so C declines; vacuum: two rewards give the same behaviour until Dump exists, then reward 2 dumps and re-sucks; design rewards for the outcome wanted.

In the Prisoner’s Dilemma (C,C = 3,3; C,D = 0,5; D,D = 1,1) defecting pays more whatever the other does (5 > 3, 1 > 0), so rational agents reach (D, D), which both rank below (C, C): a cooperation dilemma. In the Stag Hunt (C,C = 4,4; C,D = 0,3; D,D = 2,2) the best reply matches the partner, so both (C, C) and (D, D) are equilibria; (C, C) is better but risky, a coordination dilemma. In a population with 50% of each type meeting at random, C earns 2 and D 2.5 on average, so if successful strategies spread, cooperators decline.

In the vacuum world, rewarding each clean square per time step and rewarding each unit of dirt sucked produce the same behaviour with Left, Right and Suck. Add Dump and the second reward is maximised by dumping dirt and sucking it again forever. Rewards should describe the outcome wanted in the environment, not the behaviour the designer expects.

Book Ch2: Intelligent Agents

Exam questions

Is the simple reflex vacuum agent (suck if dirty, otherwise move to the other square) rational? Under what conditions, and when would it stop being rational?

Key points: rationality depends on performance measure, prior knowledge, actions and percept sequence; rational under the book’s assumptions (1 point per clean square per step over 1000 steps, known geography, deterministic actions, correct sensing); irrational if movement costs, if dirt reappears, or if geography is unknown; rationality is relative to expected performance.

A rational agent selects, for each percept sequence, the action expected to maximise its performance measure given its percepts and built-in knowledge. So “is it rational?” has no answer until we fix the four things rationality depends on: the performance measure, the agent’s prior knowledge, the available actions and the percept sequence.

Under Russell and Norvig’s assumptions the agent is rational. The performance measure gives one point per clean square per time step over 1000 steps. The two-square geography is known, but the dirt distribution and the start square are not. Clean squares stay clean, Suck cleans the current square, and Left and Right move one square (or leave the agent in place at the wall). Only Right, Left and Suck are available, and the agent correctly perceives its location and whether there is dirt. No other agent can then do better in expectation: it cleans any dirty square at once and reaches the other square in one step.

Change the circumstances and it becomes irrational. If each move costs a point, it keeps oscillating after both squares are clean and loses points; a better agent would do nothing once it is sure all squares are clean. Russell and Norvig leave that design as an exercise, but being sure takes memory: the local dirt sensor cannot see the other square, so the agent must remember having found it clean, which a simple reflex agent, acting on the current percept alone, cannot do. If clean squares can get dirty again, it should check occasionally and re-clean. If the geography is unknown, it should explore. The same agent function can be rational in one task environment and irrational in another.

Give a PEAS description for an automated taxi and classify taxi driving along each environment dimension, with a justification for each.

Key points: P: safe, fast, legal, comfortable, profitable, low impact on others; E: roads, traffic, police, pedestrians, customers, weather; A: steering, accelerator, brake, signal, horn, display, speech; S: cameras, radar, speedometer, GPS, engine sensors, accelerometer, microphones, touchscreen; partially observable, multiagent, nondeterministic, sequential, dynamic, continuous, mostly known.

PEAS. Performance: safe, fast, legal, comfortable trip, maximise profits, minimise impact on other road users (these conflict, so tradeoffs are needed). Environment: roads, other traffic, police, pedestrians, customers, weather. Actuators: steering, accelerator, brake, signal, horn, display, speech. Sensors: cameras, radar, speedometer, GPS, engine sensors, accelerometer, microphones, touchscreen.

Classification.

  • Partially observable: the taxi cannot see round a truck or know what other drivers intend.
  • Multiagent: other drivers’ behaviour is best described as maximising their own performance measures, which depend on the taxi’s actions. Partially cooperative (everyone wants to avoid collisions) and partially competitive (one parking space, one car).
  • Nondeterministic (stochastic): traffic cannot be predicted exactly, tyres blow out, engines seize.
  • Sequential: short-term actions (a lane change) have long-term consequences.
  • Dynamic: the world keeps moving while the driving algorithm deliberates; not deciding counts as doing nothing.
  • Continuous: positions, speeds, time and steering angles all vary continuously.
  • Known (mostly): the driver knows how the car and traffic rules work. Known/unknown is about the agent’s knowledge, not the environment itself; driving a rental car in an unfamiliar country would make it unknown too.

Taxi driving is therefore close to the hardest case, which is partially observable, multiagent, nondeterministic, sequential, dynamic, continuous and unknown.

Explain the difference between rationality and omniscience. Why do information gathering, learning and autonomy follow from the definition of rationality?

Key points: omniscient agent knows actual outcomes, impossible; rationality maximises expected performance, perfection actual performance (Champs Elysées example); crossing without looking is irrational, looking is information gathering; agent must learn from percepts (dung beetle, sphex wasp as failures); autonomy: rely on own percepts and learning to make up for partial or wrong prior knowledge.

An omniscient agent knows the actual outcome of its actions and can act accordingly; this is impossible in reality. Rationality only asks the agent to maximise expected performance given its percept sequence to date. Someone who crosses an empty street and is hit by a cargo door falling from an airliner acted rationally: the outcome was bad, but the choice was right given the evidence. Requiring the best action in hindsight would make the specification impossible to meet.

This does not let an agent excuse itself by not looking. Crossing a busy road with an uninformative percept sequence is not rational, because the expected cost is too high, and choosing to look first is rational, because looking raises expected performance. Acting to change future percepts is information gathering; exploring an unknown environment is another example.

The definition also requires learning from what is perceived. An agent that relies only on built-in assumptions is fragile: the dung beetle mimes plugging its nest after the dung ball is removed, and the sphex wasp repeats its drag-and-check routine endlessly when the caterpillar is moved. Neither can learn that its plan is failing. An agent that relies on its designer’s prior knowledge instead of its own percepts and learning lacks autonomy. A rational agent should be autonomous enough to compensate for partial or incorrect prior knowledge, though it is sensible to start with some built-in knowledge, as evolution gives animals reflexes.

Why is it hard to choose a performance measure? Use the vacuum world to illustrate, state Russell and Norvig's general rule, and connect it to reward hacking.

Key points: performance measure scores sequences of environment states (consequentialism); “dirt cleaned up” is maximised by dumping and re-cleaning; better: points per clean square per time step (minus energy, noise); rule: measure what you want achieved in the environment, not how the agent should behave; reward hacking: optimiser exploits the gap between measure and purpose (Wiener, King Midas), and the flaw may only appear when new actions become available (Lab 1 Dump).

Russell and Norvig judge agents by consequences: a performance measure scores the sequence of environment states the agent’s actions produce. Machines have no preferences, so the measure comes from the designer, and writing it down correctly is hard because a rational agent gives you exactly what you ask for.

If the vacuum agent is scored on the amount of dirt it cleans up in a shift, it can maximise the score by cleaning, dumping the dirt back and cleaning again. The measure described a behaviour the designer imagined. Scoring one point per clean square per time step, perhaps minus a penalty for electricity and noise, describes the state of the world the designer actually wants. Hence the rule: design performance measures according to what one actually wants to be achieved in the environment, rather than according to how one thinks the agent should behave.

The course calls this reward hacking (specification gaming), a term the book does not use: an optimiser finds behaviour that scores well on the stated objective while defeating its purpose, which is Wiener’s warning that the purpose put into the machine must be the one we really desire, and the King Midas problem. Lab 1 shows a further twist: with only Left, Right and Suck, a dirt-collected reward and a clean-floor reward produce identical behaviour, so testing cannot reveal the problem; once a Dump action is added, the dirt-collected robot dumps and re-sucks. Even a good measure leaves open questions (steady mediocre cleaning against bursts and breaks with the same average), and since the true measure may be uncertain or user-dependent, agents may need to learn it.

Distinguish the agent function from the agent program. Write the table-driven agent and explain why this approach is doomed.

Key points: agent function maps percept sequences to actions (abstract); agent program implements it, receives only the current percept; TABLE-DRIVEN-AGENT appends percept and looks up the whole sequence; table size is the sum over t of |P|^t; cannot be stored, built or learned; goal of AI is small programs that produce rational behaviour.

The agent function is an abstract mathematical description: it maps every possible percept sequence to an action. The agent program is a concrete implementation running on the agent architecture (agent = architecture + program). The program receives only the current percept, since that is all the environment provides, so if the action must depend on history the program has to remember it.

With a correct table it implements any desired agent function. But with a set of percepts P and lifetime T, the table has ∑t=1T​∣P∣t entries. For an hour of taxi driving from camera input that is over 10600,000,000,000, and even chess needs at least 10150, against fewer than 1080 atoms in the observable universe. So no agent could store the table, no designer could write it, and no agent could learn all its entries. The challenge for AI is to get rational behaviour from a compact program, as Newton’s method replaced square-root tables; even the four-line reflex vacuum agent replaces an infinite table by ignoring history.

Describe the simple reflex, model-based reflex, goal-based and utility-based agents. What does each add to the previous one, and in what kind of environment does each fail?

Key points: simple reflex: condition-action rules on the current percept, needs full observability, loops otherwise (randomisation helps a little); model-based: internal state updated with transition and sensor models, handles partial observability, still rule-based; goal-based: predicts future states and picks actions that reach goals, flexible because knowledge is explicit; utility-based: utility function grades states, handles conflicting goals and uncertain success, maximises expected utility.

A simple reflex agent chooses from the current percept alone through condition-action rules (if car-in-front-is-braking then initiate-braking). It is small and fast but works only in fully observable environments. A vacuum agent with no location sensor that always moves the same way on [Clean] loops forever in one of the two start squares; randomising between Left and Right escapes the loop, but randomisation is rarely rational in single-agent settings.

A model-based reflex agent adds internal state that tracks what it cannot currently see. It updates the state each step with a transition model (how actions change the world and how the world evolves by itself) and a sensor model (how states show up in percepts): state ← UPDATE-STATE(state, action, percept, transition model, sensor model), then matches rules as before. This handles partial observability (the state is a best guess), but behaviour is still fixed rules with no look-ahead.

A goal-based agent adds goals and uses the model to predict “what it will be like if I do action A”, choosing actions (or, via search and planning, action sequences) that achieve the goal. It considers the future and knows why it acts. It is more flexible: change the destination and the behaviour changes, whereas reflex rules would all need rewriting. But goals are binary.

A utility-based agent replaces goals with a utility function, an internalisation of the performance measure, and chooses the action with the highest expected utility, ∑s′​P(s′∣s,a)U(s′). It handles conflicting goals (speed against safety) and goals that may not be reached (weighing likelihood against importance). But modelling the world and computing the best action is hard, and perfect rationality is usually computationally out of reach.

Describe the components of a general learning agent. Why must the performance standard be fixed and outside the agent, and what is the role of the problem generator?

Key points: performance element selects actions (the old agent); learning element improves it using feedback; critic judges behaviour against a fixed performance standard; problem generator suggests exploratory actions; percepts carry no verdict on success, so a standard is needed; the agent must not adapt the standard to its own behaviour; exploration trades short-term loss for long-term gain (Galileo).

The performance element takes percepts and selects actions: it is what the earlier designs called the whole agent. The learning element improves the performance element, and its design depends on what the performance element looks like. The critic tells the learning element how well the agent is doing with respect to a performance standard. The problem generator suggests actions that lead to new, informative experiences.

The critic is needed because percepts do not say whether they are good: a chess program perceives checkmate but needs a standard to know checkmate is good. The standard must be fixed and conceptually outside the agent, because the agent must not modify it to fit its own behaviour; if it could, it could improve its score by changing the standard instead of its behaviour. The standard effectively marks part of each percept as reward or penalty, like pain and hunger in animals.

Left alone, the performance element keeps choosing the best action given what it knows. The problem generator proposes perhaps suboptimal exploratory actions that may reveal better ones in the long run, like Galileo’s experiments at Pisa. Learning in general means modifying each component of the agent to bring it into closer agreement with the available feedback, thereby improving overall performance.

Explain atomic, factored and structured representations of state with an example of each. What is gained and lost as representations become more expressive? How does a distributed representation differ from a localist one?

Key points: atomic: state is a black box (city name; search, MDPs); factored: fixed set of variables with values (fuel, GPS, money; CSPs, propositional logic, Bayesian networks); structured: objects with attributes and relations (truck, cow, driveway; first-order logic, databases); more expressive is more concise (chess rules: a page or two, thousands of pages, about 10^38 pages) but harder to reason and learn with; localist one concept per location, distributed spread over many, robust to noise.

In an atomic representation a state has no internal structure: for route-finding it is just the name of the city you are in, and two states are only ever the same or different. Search, game playing, hidden Markov models and Markov decision processes use atomic states. A factored representation splits the state into a fixed set of variables with values: fuel level, GPS position, toll money. Two states can share some values, which makes it easier to see how to turn one into another; constraint satisfaction, propositional logic, planning and Bayesian networks use it. A structured representation describes objects, their attributes and their relations, which a scene like a truck reversing into a farm driveway blocked by a loose cow needs; first-order logic, relational databases and natural language understanding use it.

More expressive representations capture everything less expressive ones can, usually far more concisely: the rules of chess take a page or two in first-order logic, thousands of pages in propositional logic and about 1038 pages as a finite-state automaton. The cost is that reasoning and learning get harder, so real systems may need all three levels at once.

A localist representation maps each concept to one memory location; a distributed representation spreads each concept over many locations, each shared with other concepts. Distributed representations are more robust: a few garbled bits move the concept to a nearby point with similar meaning, while in a localist code they can turn Truck into the unrelated Truce.

Lab01: Simple Agents, Complex Dynamics

Exam questions

A symmetric game has R=5, S=0, T=3, P=1. Find the pure Nash equilibria, the Pareto-optimal outcomes and the social optimum, compute p∗, say which equilibrium uniform-belief agents play more often, and give the replicator rest points with their stability.

Key points: Nash (C,C) and (D,D), a Stag Hunt (fear, no greed); only (C,C) Pareto optimal and socially optimal; p∗=1/3; (C,C) more often since R−T=2>P−S=1, with Pr(C,C)=4/9; rest points 0 stable, 1/3 unstable, 1 stable.

Game. R>T>P>S, so it is a Stag Hunt: no greed (T=3<R=5), fear (P=1>S=0).

Nash. At (C,C) deviating gives 3 < 5; at (D,D) deviating gives 0 < 1; at (C,D) the cooperator gains by switching to D (1 > 0). Pure equilibria: (C,C) and (D,D).

Pareto and social. Payoffs (5,5), (0,3), (3,0), (1,1). (C,C) beats every other cell for both players, so it is the only Pareto-optimal outcome, and with welfare 10 (against 3, 3 and 2) the social optimum.

Threshold. p∗=(R−T)+(P−S)P−S​=2+11​=31​. Stag is the best response when the belief that the partner hunts stag exceeds 1/3.

Uniform beliefs. Each agent cooperates with probability 2/3: Pr(C,C)=4/9≈0.44, Pr(D,D)=1/9≈0.11, miscoordinated 4/9. (C,C) is more frequent, as the rule R−T>P−S (2>1) predicts.

Replicator. fC​−fD​=x(R−T)+(1−x)(S−P)=2x−(1−x)=3x−1, so x˙=x(1−x)(3x−1). Rest points 0 (stable, g′(0)=S−P=−1), 1/3 (unstable), 1 (stable, g′(1)=T−R=−2). Populations starting above 1/3 cooperators end at full cooperation, below at full defection.

A symmetric game has R=3, S=1, T=4, P=0. Find the pure Nash equilibria, the replicator rest points and their stability, and explain how the long-run population differs from the Stag Hunt's.

Key points: greed present, fear absent; pure Nash (C,D) and (D,C), no symmetric pure equilibrium; fC​−fD​=1−2x; rest points 0 and 1 unstable, x=1/2 stable; population converges to a mix, while the SH’s interior point is unstable.

Motives. Greed: T=4>R=3. Fear absent: P=0<S=1. Each player wants to do the opposite of the other.

Nash. Against C the best response is D (4 > 3); against D it is C (1 > 0). So the pure equilibria are (C,D) and (D,C); (C,C) and (D,D) are not equilibria. Social optimum: (C,C) with welfare 6 (against 5, 5, 0).

Replicator. fC​−fD​=x(R−T)+(1−x)(S−P)=−x+(1−x)=1−2x, so x˙=x(1−x)(1−2x). Rest points: x=0 with g′(0)=S−P=1>0, unstable; x=1 with g′(1)=T−R=1>0, unstable; x∗=1/2, where g′(1/2)=21​⋅21​⋅(−2)=−21​<0, stable. From any interior start the population goes to half cooperators.

Contrast. In the SH (R>T, P>S) both pure states are stable and the interior rest point (the mixed equilibrium) is unstable, a tipping point. Here both pure states are unstable (a rare strategy always earns more) and the interior rest point, the mixed equilibrium with cooperation probability 1/2, is where the population ends. Whether adaptation ends at the mixed equilibrium depends on the signs of S−P and T−R.

In a repeated Prisoner's Dilemma ( R=3,S=0,T=5,P=1), explain why memory matters, why AllD can still top a round robin with AllC, AllD, Random, TFT and WSLS over 50 rounds, and from how many rounds TFT beats AllD in a field of AllD, TFT and WSLS.

Key points: memory-0 strategies cannot react, memory-1 strategies condition on the last outcome; TFT loses only round 1 to AllD; AllD’s score comes from exploiting AllC (5), Random and WSLS (about 3 each); in the three-strategy field AllD wins for 1 to 3 rounds and TFT from 4.

Memory. A memory-0 strategy (AllC, AllD, Random) plays the same way whoever it meets, so a cooperator of this kind is exploited every round. A memory-1 strategy conditions on the previous outcome: TFT cooperates with cooperators and defects against AllD from round 2, so it loses 5 points once and then gets 1 per round (0.98 per round over 50).

Why AllD tops the five-strategy field. Its 50-round score, about 2.62, averages 5 against AllC, 1 against itself, 3 against Random, 1.08 against TFT and 3 against WSLS, which alternates C and D against it. Most of its points are temptation payoffs taken from AllC, Random and WSLS; against TFT it earns little. TFT is second at about 2.44.

Crossover. Per-round tournament scores times 3 over n rounds: AllD 5+4/n (n even) or 5+6/n (n odd); TFT 7−1/n; WSLS 6+⌊n/2⌋/n. AllD beats TFT iff n<2.5 (even) or n<3.5 (odd), so AllD is best for 1, 2 and 3 rounds and TFT from 4 rounds on.

Derive the two-strategy replicator equation's factorised form, use it to show that cooperation always dies out in a Prisoner's Dilemma, and explain why the Stag Hunt's interior rest point equals the threshold belief p∗ even though adaptive agents hold no beliefs.

Key points: x(fC​−fˉ​)=x(1−x)(fC​−fD​); PD: fC​−fD​=x(R−T)+(1−x)(S−P)<0 by greed and fear; x=1 is a rest point but unstable; random matching makes the share x play the role of the belief p; the same indifference equation gives the same solution.

Factorisation. fˉ​=xfC​+(1−x)fD​, so fC​−fˉ​=(1−x)(fC​−fD​) and x˙=x(1−x)(fC​−fD​).

PD. fC​−fD​=x(R−T)+(1−x)(S−P). Greed gives R−T<0, fear gives S−P<0, so for every x∈[0,1] it is a weighted average of two negatives. Hence x˙<0 on (0,1) and every population with some defectors goes to x=0, matching the unique Nash equilibrium (D,D). x=1 is a rest point because there is nobody to copy, but a single defector earns T>R and spreads.

Why x∗=p∗. With random pairing, a partner cooperates with probability equal to the population share x. So fC​(x)=xR+(1−x)S is exactly πC​(p) with p=x, and likewise for D. The interior rest point solves fC​=fD​, the same equation as the rational agent’s indifference πC​(p)=πD​(p), so x∗=(R−T)+(P−S)P−S​=p∗. The rational agent cooperates when its belief exceeds p∗; in the population, cooperators grow when the actual share exceeds p∗. For the lab’s SH it is 2/3, and it is unstable: a tipping point.

In the signalling game with λ=0.3, b=g=d=1 and cH​=0.2, explain the long-run outcomes for cL​=1.5 and cL​=0.5, and evaluate a designer's uniform fee of k=1 on the label.

Key points: cL​>b: fakers die out, honest separating outcome, reliability 1, receivers earn 0.3; cL​<b: cycles around y=0.5, xL​=3/7, reliability about 0.5, receivers earn about 0; fee makes cH​=1.2>b, nobody signals, welfare 0.084 to 0; honesty needs cH​<b<cL​.

Expensive faking (cL​=1.5). Faking pays at most b−cL​<0, so xL​→0. H signals whenever y>0.2; once fakers are rare trusting pays (0.3xH​>0.7xL​), so y→1 and xH​→1. The signal is fully reliable; receivers earn 0.3 and H sellers 0.8.

Cheap faking (cL​=0.5). Faking pays when y>0.5; trusting pays when xL​<3/7 (with xH​=1). No state satisfies everyone, so trust and faking chase each other in cycles around y=0.5, xL​=3/7. Reliability averages about 0.5 (prior 0.3) and receivers average about 0: fakers keep the signal just bad enough that trusting pays no better than scepticism (since dtd​ln1−yy​ equals the advantage of trusting and y stays bounded, that advantage averages about zero).

The fee. With k=1, cH​=1.2 and cL​=1.5 both exceed b, so nobody signals. Deception ends, but receivers stay at 0, H sellers drop from about 0.3 to 0 and welfare from 0.084 to 0. The fee is harmful.

Correct design. An honest signal needs cH​<b<cL​: affordable for genuine sellers, unprofitable for fakers. A uniform fee shifts both costs equally and could at most place b between them (0.5<k<0.8 here); a cost that falls on fakers specifically (verification they fail, penalties) is the right tool.

Two robot vacuums plan optimally with value iteration ( γ=0.95) in the two-square vacuum world with dirt rate 0.1. Bob's reward is +1 per clean square per step; Alice's is +1 per unit of dirt sucked. Explain why tests in the lab cannot tell them apart, what happens when a Dump action is added, and what this shows about agents and tools.

Key points: identical optimal action sets in all 16 states without Dump, so identical behaviour; Alice dumps when the bag is full and her square is clean, then re-sucks for +1 every two steps (floor 84% to 59% clean, dirt collected 0.196 to 0.527 per step); Bob never dumps; reward hacking: a proxy that matched the goal under one action set diverges when a new action appears.

Lab. With Left, Right and Suck, a square becomes clean only by being sucked and dirt only comes from the environment, so maximising clean squares and maximising dirt sucked call for the same actions: suck when on dirt, move to dirt, anything on a clean floor. Both robots have the same optimal set in every state and act identically step for step; no behavioural test in this environment can reveal the reward.

With Dump. Alice’s robot dumps in the four states with a full bag and a clean current square (uniquely when both squares are clean, tied with moving when the other square is dirty), then sucks the same dirt: +1 every two steps, guaranteed. It dumps on 40% of steps, its floor drops to about 59% clean, it barely moves. Bob’s reward ignores the bag and penalises dirt, so dumping only loses reward; he never dumps.

Lesson. Nobody programmed dumping: a perfect optimiser found a way to raise a proxy (dirt collected) without serving the goal (a clean floor). New actions or tools can break the link between reward and goal, testing behaviour cannot certify a reward, and rewards should target outcomes and be re-checked whenever capabilities change.
